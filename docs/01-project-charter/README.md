# Admission Workflow Management System

## Project Vision

To design and develop a fair, transparent, and efficient on-campus admission workflow management system that streamlines the admission process after students arrive at the university. The system aims to reduce manual effort, minimize waiting time, prevent queue jumping, and provide a structured admission experience for both students and university staff.

---

## Problem Statement

The university already provides an online admission portal through which students submit their applications and receive a unique Application ID. However, the on-campus admission process remains largely manual and becomes difficult to manage when a large number of students arrive on the same day.

During the admission process, several operational issues were observed, including:

* Queue jumping and unfair processing of students.
* Long waiting times due to manual workflow management.
* Manual verification of documents and payment transactions.
* Students being unsure of the next step in the admission process.
* Heavy dependence on paper forms and physical approvals.
* Difficulty handling special cases such as installment payments and multiple payment transactions.

These issues reduce operational efficiency and create an inconsistent admission experience for both students and university staff.

---

## Project Objectives

The primary objectives of this project are to:

* Digitize and track the on-campus admission workflow.
* Create a fair and structured First Come, First Served (FCFS) queue management system.
* Improve visibility of each student's current workflow stage.
* Support the existing physical document workflow instead of replacing it.
* Support payment verification for both manual and online payment methods, including installment-based payments.
* Build a modular system that can be enhanced as new technologies are learned and incorporated in future versions.

---

## Scope (Version 1)

Version 1 of the project will focus on developing a Command Line Interface (CLI) application using Python.

The system will begin when a student arrives on campus with a valid Application ID generated by the university's existing admission portal.

The initial version will include:

* Student arrival registration using an existing Application ID.
* FCFS queue token generation.
* Workflow stage tracking throughout the on-campus admission process.
* Physical document workflow tracking.
* Approval workflow management.
* Manual payment verification by authorized staff.
* Recording verified payment details.
* Receipt generation simulation.
* Support for future online payment integration through a modular design.



---

## Out of Scope (Version 1)

The following features are intentionally excluded from Version 1:

* Online admission application portal.
* Student document upload and storage.
* Direct payment processing.
* Online payment gateway integration.
* Banking system integration.
* Integration with the university's ERP or financial systems.
* Automatic payment verification.
* Graphical User Interface (GUI).
* Web application.
* Mobile application.
* Database integration.
* REST APIs.
* User authentication and authorization.
* Real-time notifications.
* Cloud deployment.


These features are planned for future versions as the project evolves.

---

## System Boundary

The Admission Workflow Management System begins when a student arrives at the university with a valid Application ID generated by the university's existing admission portal.

The system is designed to support and manage the on-campus admission workflow by tracking each student's progress through workflow stages using a unique queue token. Physical documents remain part of the admission process and continue to move with the student throughout the workflow.

The system does not replace the university's online admission application process, physical document verification, or payment infrastructure. Instead, it coordinates and tracks the workflow until the student's admission process is successfully completed.

## Success Criteria

The project will be considered successful if it achieves the following outcomes:

* The on-campus admission workflow is clearly defined and digitally tracked.
* Queue jumping and unfair processing are minimized through FCFS token management.
* Students and staff can easily track the current workflow stage and next step for every admission token.
* Payment verification becomes simpler and more organized for both manual and online payments.
* Administrative tasks require less manual coordination.
* The system integrates seamlessly with the existing paper-based admission process.
* The project provides a strong foundation for future web-based, database-driven, and API-enabled versions.
